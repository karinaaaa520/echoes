## 1. 第一关软锁（R-7）

### 1.1 现象

第一关出口原本在右上角 (5,1)。影子在同一格停下后，本体**永远进不去**，只能按 R 重开。

机制原因（不是巧合，是规则必然）：

- 影子先动、本体后动，且**本体不能进影子所在的格子**。
- 本体要进 (5,1)，只能从 (4,1) 按 R 或从 (5,2) 按 U。
- 影子在 (5,1) 时，它"让开"的方向必须是上一拍输入的方向。若上一拍是 R，影子撞右墙不动；若上一拍是 U，影子撞上墙不动 —— 而本体恰恰只能从这两个方向接近。
- 于是形成闭环：要进就按 R/U，按 R/U 影子就不动。

穷举验证（`docs/tools/level_check.py`）：**177 个可达状态里 72 个是死局**，其中 **7 个**正是"影子停在出口格"。

### 1.2 为什么"把出口挪到右墙中段"不管用（重要）

第一版修法是把出口从 (5,1) 挪到 (5,2)（右侧墙中段）。推理上是"多了上下两条退路"，但实测：

```
A 方案 出口(5,2): 最短 5 拍，死局 72 / 177      ← 完全没改善
```

进一步查死局结构才发现：**死局不是"影子停在出口"，而是一整片"影子把本体挡在右墙外"的封闭区**。  
死局里本体只出现在 x=1..4，影子出现在 x=2..5 —— 影子像一堵会走的墙，把本体挤在左半边。  
而影子让开的方向受"上一拍输入"约束，本体又只能从左右接近，两者互相锁死。

这次失败说明：**这个规则下的软锁不能靠"看起来合理"去推，必须穷举所有可达状态。**

### 1.3 最终修法：出口移到顶墙中段

```text
改前（7×5）              改后（7×5）
#######                  #######
#P...E#                  #..E..#      ← 出口 (3,1)，左右 (2,1)(4,1) 都是地面
#.....#                  #.....#
#..S..#                  #P.S..#      ← 起点移到左下，影子在下方中间
#######                  #######
```

关键几何：**出口左右都是地面**，所以本体从左侧按 R 时，影子可以继续向右让开（它有地方去）。  
这就是"墙角"与"墙中"的本质区别 —— 不是"多了几条路"，而是**影子有退路**。

数据对比：

| 指标        | 改前         | 改后         |
| --------- | ---------- | ---------- |
| 可达状态      | 177        | 73         |
| 死局        | **72**     | **0**      |
| 影子停在出口的状态 | 16         | 6          |
| 其中仍可通关    | 2          | **6（全部）**  |
| 最短解       | R R R R（4） | U U R R（4） |

### 1.4 教学定位没变，还多教了一条

- 仍是 7×5、无钥匙/门/压力板、4 拍，只教"方向键"和"影子慢一拍"。
- 多了一个天然的教学瞬间：**第 3 拍影子正好停在出口格上，但不算通关** —— 屏幕上会先看到影子"站进了出口"，下一拍才由本体真正完成。规则里"只有本体能通关"于是不需要文字解释。
- 另一种走法 `R R U U` 同样 4 拍通关，新手怎么绕都能过。

### 1.5 永久回归守卫

新增 `echoes/tests/test_level1.gd`（8 组 36 条），其中两组是本轮的核心：

1. **[5] 复现场景**：`U U U` 把影子逼到出口 → 再 `R R` 仍能通关（旧版在这里永久卡死）。
2. **[6] 全状态穷举**：枚举 67 个可达状态，断言**死局为 0**；并逐个检查"影子停在出口"的 6 个状态，全部可赢。

为了让这条守卫不"空转"，同一段测试里加了一组**对照**：把出口放回角落，跑同一套搜索，**必须报出死局**：

```
[PASS] 死局为 0（旧版是 72 个）
[PASS] 确实存在影子停在出口的状态（否则这条回归是空转）
[PASS] 这些状态全部仍可通关
    对照组（角落出口）：可达 173 个，死局 72 个
[PASS] 对照组确实被判为有死局（守卫有效）
```

> 注：Python 与 GDScript 的状态数略有差异（73 vs 67）——引擎在通关后会拒绝输入，所以 GDScript 不再展开"已通关之后"的状态；两者对死局数的结论一致。

### 2.3 审查发现（按严重度）

**F-1（高）关卡提示从不显示**  
`levels.gd` 里 4 条提示写得挺准，但 `main.gd` / `world_view.gd` 从未读取 `hint` 字段（全仓库只有 `win_hint_label` 这个 UI 变量同名，与关卡提示无关）。  
新玩家进游戏看到的是一张没有任何文字的地图，只能靠试。四关的核心机制（"你的影子被关在里面"）**全靠自己发现**。  
→ 建议：在关卡开始显示 2 秒提示条。技术障碍是 Godot 内置字体没有中日韩字形（P0 阶段就踩过），需要引入一份子集字体，或先上英文版提示。

**F-2（中）墙与地面对比度偏低**  
墙体 `#3d3d49`、地面 `#23232b`，两者亮度接近。截图上要靠网格线才能分辨房间边界。  
→ 建议：把墙提亮一档，或给地面加轻微纹理（属表现层，需你点头）。

**F-3（中）小地图在画面里太小**  
逻辑分辨率 320×180，而 L1 只有 112×80 像素（约占画面 1/3），缩在正中间像一张邮票；L3/L4 也只有 176×128。  
→ 建议：按关卡尺寸做整数倍缩放（L1/L2 用 2×，L3/L4 用 1×），保持像素对齐不失真。这是 `world_view` 里的一处缩放，不改美术。

**F-4（低）壁龛的"进不去"没有任何心理预期**  
L2/L3/L4 的核心都是"一块板在墙里"。玩家第一次看到时会先尝试走进去，撞墙后才明白。  
→ 建议：给壁龛边缘画一圈更暗的描边，或让壁龛内的地砖颜色略深，形成"这是个坑/笼子"的视觉语汇。

**F-5（低）通关面板是一个不透明的灰块**  
`WinOverlay` 的底板把地图压暗后仍留着明显矩形边界，观感像弹窗而不是气氛叠层。  
→ 建议：底板改全屏半透明，或去掉底板只留文字 + 轻微暗角。

### 2.4 第四关专项：往返路线是否真的必要

用户特别要求确认"影子是否真正需要完成左侧与右侧压力板的往返"。结论：**是，而且是强制的**。

- **几何上**：壁龛是 `(6,5)(7,5)(8,5)` + `(6,6)=b` + `(8,6)=p`，两齿之间 `(7,6)` 是墙。b 与 p 的曼哈顿距离是 2，但**没有直连**。
- **实测路径**（引擎日志）：影子 `(7,5) → (6,5) → (6,6)=b`（第 3 拍）→ `(6,5) → (7,5) → (8,5) → (8,6)=p`（第 12 拍）。  
  从 b 到 p 实际走了 **4 步**，是直线距离的 2 倍 —— 必须退回干道再折向另一侧。
- **顺序**：先左后右、先右后左都成立（对称），但两种顺序都包含同样的往返，无法"顺路"完成。
- **必要性**：出口要 a+b+p，b、p 都在壁龛内，本体可达 33 格与壁龛 5 格零交集（`test_level4` 断言 `overlap == 0`）。

## 7. 下一阶段建议

1. **先解决 F-1**（提示不可见）。这是唯一一个"玩家可能根本不知道游戏怎么玩"的问题，优先级高于任何关卡内容。最小方案：引入一份 12px 中日韩子集字体（约 200KB），或在关卡开场用英文提示条。
2. **再做 F-3**（按关卡整数倍缩放）。四关尺寸差异大，放大后小关卡的第一印象会明显变好，改动只在 `world_view`。
3. **然后 F-2 / F-4**（对比度与壁龛视觉语汇），可以和美术替换一起做。
4. 关卡内容层面四关已闭环（0 死局、影子必需、难度递进），建议**不要再加第五关**，把时间投在表现与音效上 —— 比赛评分里"完成度"往往比"关卡数"更值钱。
5. 提交前补两件事：真实 Release 包与一个 60~90 秒的游玩录屏（"影子先动"目前仍只有日志证据）。
