## 一、验证器修复（任务一）

### 1.1 问题定位

`docs/tools/level_check.py` 的 `shadow_no_plates_solve()` 里，四个候选方向共用同一组变量：

```python
for d in DIRS:
    ...
    if lv.at(t) in 'D+' and t not in doors:
        if hk:
            doors, hk = doors | {t}, False   # ← 直接改写了外层 doors / hk
```

`doors` 和 `hk` 在 `for d` 循环外、`while` 循环内解包，所以**上一次迭代开过的门、耗掉的钥匙会带进下一次迭代**。后果是"分支 A 把钥匙花在一扇死路门上，分支 B 就再也开不了正确的门"，即把可通关误判为不可通关。

（同类代码 `player_only_solve()` 没有这个问题：它在每个分支开头有 `nhk, ndoors, nkeys, nlat, np_ = hk, doors, keys, latched, t` 这一行独立副本。）

### 1.2 复现（A 类证据）

构造一张 10×6 的小图：钥匙就在 (3,2)，它的**正上方** (3,1) 是一扇死路门，真正的出口门在 (6,2) 后面。

```
##########
###D#####S
#P.K..D###
######.###
######E###
##########
```

正解必须「拿着钥匙从 (3,2) 走开」，而不能顺手开头顶那扇门。因为 `DIRS` 的遍历顺序是 `U, D, L, R`，`U` 分支总是先开掉死路门并吃掉钥匙。

| 版本 | 结果 |
|---|---|
| 旧版（有污染） | **不可通关**（漏解） |
| 修复版 | **可通关 `R R R R R R D D`（8 拍）** |

修复版给出的解已被一份**独立实现的重放器**逐拍验证（`test_level_check.py` 里的 `replay_no_plates`）：重放时每一拍的开门/拾取/压板都按真实规则重算，最终本体确实站在出口上。

## 二、音效（任务二）

### 2.1 资源方案：全部代码合成，零版权风险

| 方案 | 结论 |
|---|---|
| 网上下载素材 | ❌ 版权不明，不采用 |
| 开源音效库（CC0） | 需联网下载，本轮网络不稳；且质量参差 |
| **用代码合成 WAV** | ✅ 采用：波形由数学公式生成，不存在可争议的来源；可复现；体积小 |

生成器：`docs/tools/make_sfx.py`（纯标准库，确定性伪随机，重跑字节完全一致）。

规格：**22050 Hz / 单声道 / 16-bit / 不循环**。22050 而不是 44100，是因为音效都很短，减半采样率听感无可辨差异但体积减半。

| 音效 | 时长 | 设计 | 大小 |
|---|---|---|---|
| `step_player` | 55 ms | 720Hz 方波经低通，短促干脆 | 2.4 KB |
| `step_shadow` | 85 ms | 300Hz 方波（更闷）+ 150Hz 正弦垫底，比本体**低一个八度、略长** → 一听就能分开 | 3.7 KB |
| `plate` | 140 ms | 880→1320Hz 两级上行"叮" | 6.1 KB |
| `key` | 170 ms | 988/1319/1661Hz 三连音琶音 | 7.4 KB |
| `door` | 200 ms | 150Hz 低频"咚" + 木质噪声 | 8.7 KB |
| `exit_open` | 300 ms | 440→880Hz 上滑 + 1760Hz 微光 | 13.0 KB |
| `win` | 560 ms | 523/659/784/1047Hz 四音上行 | 24.2 KB |
| **合计** | | | **65.3 KB** |

### 2.2 实现

新增 `scripts/sfx.gd`（`class_name Sfx`）：

- `CUE_PATHS` 常量表暴露 7 个音效路径，测试可直接遍历检查；
- **6 个 `AudioStreamPlayer` 轮转池**，新音效不掐掉上一个的尾巴；
- `play()` 立即返回，**不 await、不阻塞**，因此不可能改变回合结算时序；
- 音量四档 `100% / 50% / 25% / OFF`（0 / -6 / -12 / -80 dB），`cycle_volume()` 循环；
- `cue_played(cue)` 信号：让"影子先响、本体后响"这个**顺序**可以被自动化断言；
- `_exit_tree()` 停止并清空播放器（详见 6.2 的退出告警处理）。

**声音与画面的时序**（`world_view.gd`）：

```gdscript
if r.shadow_moved:
    _play("step_shadow")              # 立刻响
_tween.tween_property(shadow, ...)
_tween.tween_callback(func(): if r.player_moved: _play("step_player"))   # 60ms 后
_tween.tween_property(player, ...)
```

影子先响、本体后响，与画面完全同序。**撞墙的拍子完全静音**（否则节奏会糊）。

**机关音**由 `main.gd` 的 `_play_mechanism_cue()` 在一拍开始时触发，若同一拍发生多件事，只播最重的一个：
`exit_open > door > key > plate`。

## 三、提示可重看（任务三）

### 3.1 结论：值得做，已实现

评估：提示 3 秒后淡出，但四关的核心机制（尤其"影子被困在壁龛里"）玩家往往要试错几拍才反应过来，此时提示已经消失。加一个**零成本、零副作用**的查看键收益明显。

### 3.2 实现

| 位置 | 改动 |
|---|---|
| `project.godot` | 新增动作 `show_hint`（H，physical_keycode 72）、`cycle_volume`（M，77） |
| `input_router.gd` | 新增 `hint_requested` / `volume_requested` 信号；两者都在 R 之后、方向键之前处理，**不看回合锁**，且**不碰 `buffered` 与 `locked`** |
| `main.gd` | `_on_hint_requested()` 重新显示本关提示；`_on_volume_requested()` 循环音量并在提示条显示 `VOL xx%` |

关键设计：H 与 M 走的是"看/听"的通道，和 R 一样**绕过回合锁**，但**绝不触碰输入缓冲**——所以动画期间按 H，缓存的方向仍会在动画结束后照常执行。

`_show_hint()` 增加可选参数 `hold`，音量提示用 0.9 秒，关卡提示仍 2.4 秒。

## 六、本轮踩到的两个坑（都值得记住）

### 6.1 20 秒兜底计时器会截断四关连打

`_capture_if_requested()` 里有个"20 秒后无论如何退出"的保底。四关连打要按 50 次键、中间还有 3 次等 1.3 秒的切关，总耗时 12 秒左右——但机器一忙就会顶到 20 秒，表现为"第四关只走了一半就没了 turn 日志"。

已把保底放宽到 **60 秒**并注释原因。这个坑的隐蔽之处是：它看起来像"按键注入失效"，实际是自检工具自己退了。

### 6.2 音效播放中退出会打印两条"泄漏"告警

```
WARNING: 2 ObjectDB instances were leaked at exit
ERROR: 1 resources still in use at exit
```

只在**进程退出的瞬间还有音效在播**时出现（静音通关则完全不出现；通关后等 1 秒再退也不出现）。这不是运行期错误，但会污染自检日志、也会误导读日志的人。

处理：
- `Sfx._exit_tree()` 里 `stop()` + 清 `stream`，覆盖玩家关窗口的情况；
- 自检工具在截图后先停掉所有播放器、等 0.2 秒（给音频线程几个混音块的时间）再 `quit()`。

处理前后对照（各跑 2 轮 4 个场景）：**8/8 干净**。注释里写明了"音频线程是异步的"这个原因，避免以后有人把这段当成冗余代码删掉。
