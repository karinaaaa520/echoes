## 3. 调试功能的 Debug / Release 隔离

### 3.1 隔离方式

所有自检入口收敛到一个判定：

```gdscript
## Release 导出后 OS.is_debug_build() == false，所有开关自动失效
func _dev_tools() -> bool:
    return OS.is_debug_build()
```

三个使用点：

| 开关 | 守卫位置 | Release 下的行为 |
|---|---|---|
| `--shot` / `--keys` / `--keydelay` | `_capture_if_requested()` 首行 `if not _dev_tools(): return` | 截图与按键注入整段不执行，进程正常游玩 |
| `--fixture` | `if _dev_tools() and _has_user_arg("--fixture")` | 条件短路，**即使传参也只会进正式第 1 关** |
| 调试标签 | `debug_label.visible = _dev_tools()` | 不显示 |

### 3.2 实测对照

**必须说明：本机未安装导出模板**（`~/Library/Application Support/Godot/export_templates/` 为空目录），因此本轮**无法产出真正的 Release 二进制**。

替代做法：把 `_dev_tools()` 临时改为 `return false`（模拟 Release 的判定结果），跑同一组参数，对照两种状态的行为，跑完立即还原。

| 观测项 | Debug（真实） | 模拟 Release（`_dev_tools()=false`） |
|---|---|---|
| 启动日志 | `debug_build=true dev_tools=true debug_label=true` | `debug_build=true dev_tools=false debug_label=false` |
| 传 `--fixture` 后加载的关卡 | `机关测试室 9×5` | **`回声初醒 7×5`（回落到正式第 1 关）** |
| 调试标签 | 可见 | **不可见**（日志中 `debug_label=false`） |
| 传 `--shot` 是否截图 | 输出 `[capture] … err=0` | **无任何 capture 行** |
| 传 `--keys=RRRR` 是否注入 | 4 个回合 | **0 个回合**（完全没有 `[turn]` 行） |

结论：**在 `_dev_tools() == false` 的条件下，四项调试能力全部失效，且不会误入测试室。** 剩下唯一的假设是"Release 模板下 `OS.is_debug_build()` 返回 false"——这是引擎契约，不是我们的代码逻辑。

### 3.3 尚未闭环的一点

真实 Release 二进制的验证要等导出模板装好（P3 阶段）。届时用这条命令即可一次性确认：

```bash
# 导出后运行，若仍加载「机关测试室」就说明隔离失效
./build/macos/Echoes.app/Contents/MacOS/Echoes -- --fixture --shot=/tmp/should_not_exist.png
ls /tmp/should_not_exist.png   # 期望：No such file
```

已记入遗留问题 R-1。
