# 《影迹 Echoes》Godot 4 技术架构与 H5 导出方案

**版本：** v1.0  
**日期：** 2026-11-13  
**前提：** 采纳审查报告的建议——顺序结算（方案 A）、开启事件一律锁存、不加空格等待  
**约束：** 单人开发 / 初学者 / 23 天工期 / 必须能稳定导出 H5

---

## 0. 技术选型

| 项   | 选择                                         | 理由                                      |
| --- | ------------------------------------------ | --------------------------------------- |
| 引擎  | **Godot 4.7.2 stable**（2026-08 发布，当前最新稳定版） | 全程锁定这个版本，**中途绝不升级**（4.8 还是 beta，不碰）     |
| 语言  | GDScript                                   | 官方一等支持，Web 导出无需额外运行时                    |
| 渲染器 | **Compatibility（GL Compatibility）**        | H5 唯一稳妥选择；Forward+ / Mobile 的 Web 支持不可靠 |
| 分辨率 | 视口 **320×180**，图块 **16×16**                | 整数倍放大到 1280×720 / 1920×1080 都正好，无半像素    |
| 拉伸  | `canvas_items` + `keep` + **integer** 缩放   | 像素不糊、不抖                                 |
| 物理  | **完全不用**                                   | 见 §3                                    |
| 动画  | `Tween`（代码创建）                              | 不建 AnimationPlayer、不建动画状态机              |
| 架构  | 单场景 + 纯逻辑回合求解器                             | 见 §1                                    |

> 选 4.7 而不是 4.4/4.5：4.4 已 EOL，4.5 仅安全维护，4.7 是当前唯一"全支持"的稳定分支，且自带 `VirtualJoystick` 等 UI 便利（本项目用不上，但编辑器稳定性更好）。**不要用 4.8 beta。**

## 1. 架构总原则：三句话

1. **规则是纯数据 + 纯函数，不挂在节点上。** 一个 `TurnResolver` 对象只保存整数坐标和布尔值，`step(方向)` 返回结果和事件，不碰任何节点、不播动画、不 `await`。
2. **表现层只是"把结果画出来"。** `WorldView` 收到事件后补间移动精灵、播放音效。
3. **只有一个场景在跑。** 标题、关卡、结尾都是 `Main.tscn` 里的叠层，用 `visible` 切换，不做 `change_scene`。

这样做的好处非常实际：

- 逻辑可以在**无头模式**下跑单元测试，不用开窗口；
- 同一份逻辑可以直接喂给**穷举验证器**（审查报告附录 A 的 BFS），改一张图 1 秒验证是否无解；
- 出 bug 时，问题一定在"逻辑算错"或"画面没跟上"二者之一，不会搅在一起。

### 数据流（一拍）

```
玩家按键
  ↓
InputRouter    过滤重复输入 / 回合锁 / 单格缓冲
  ↓  Vector2i 方向
TurnResolver.step(dir)          ← 纯逻辑，10 行，无节点依赖
  ↓  {player_moved, shadow_moved, key, door, exit, win} + 新状态
WorldView.play(events)          ← 影子先动 → 本体后动（顺序和规则一致）
  ↓  await tween.finished
InputRouter 解锁 → 消费缓冲的下一拍
```

> **注意动画顺序**：规则是"影子先结算"，所以**画面也必须让影子先动**（间隔 60ms）。玩家只有看见"影子先走、本体后走"，才能建立时序直觉。如果两个一起动，这个游戏最重要的一课就丢了。

## 3. 网格地图与碰撞：不用物理引擎

### 为什么不用 `CharacterBody2D` + `move_and_slide`

| 物理方案的问题                        | 网格解谜的后果             |
| ------------------------------ | ------------------- |
| 位置是浮点，碰撞后会被"挤出"微小距离            | 角色不在格心，下回合判定出错      |
| `move_and_slide` 遇到斜角会**沿墙滑行** | 玩家按"右"却贴着墙往下挪，规则被破坏 |
| 物理帧 `_physics_process` 与输入不同步  | 快速连按丢步或多步           |
| 无法离线穷举                         | 无法自动验证关卡是否有解        |

**结论：碰撞 = 查一次二维数组。** 零误差、零延迟、可穷举。

```gdscript
# turn_resolver.gd 片段
const WALL := 0
const FLOOR := 1
const DOOR := 2
const KEY := 3
const EXIT := 4
const PLATE := 5

var grid: Array[PackedInt32Array]   # grid[y][x] = 上表的常量
var w: int
var h: int

func cell(p: Vector2i) -> int:
    if p.x < 0 or p.y < 0 or p.x >= w or p.y >= h:
        return WALL                 # 越界即墙
    return grid[p.y][p.x]

func is_blocked(p: Vector2i) -> bool:
    match cell(p):
        WALL:
            return true
        DOOR:
            return not doors_open.has(p)
        EXIT:
            return not exit_open    # 关闭的出口等同墙（审查建议 P1-4）
    return false
```

### 坐标与像素

```gdscript
const TILE := 16
func cell_to_px(c: Vector2i) -> Vector2:
    return Vector2(c) * TILE + Vector2(TILE, TILE) * 0.5   # 格心
```

角色精灵设为 16×16、`centered = true`，直接 `position = cell_to_px(cell)`。**永远不要在逻辑里出现浮点坐标。**

### 关卡数据（`levels.gd`）

ASCII 是唯一数据源，改关卡就是改字符串，不打开编辑器也能改：

```gdscript
extends Node
const LEVELS := [
{
  "name": "回声初醒",
  "hint": "方向键移动。影子会重复你上一拍走的方向。",
  "map": [
    "#######",
    "#P...E#",
    "#.....#",
    "#..S..#",
    "#######",
  ],
  "exit_needs": [],          # 空 = 出口一开始就是开的
},
{
  "name": "两处微光",
  "hint": "走不动的那一步，也是时间的一步。",
  "map": [
    "#########",
    "#P..a..E#",
    "#.......#",
    "#..S..b.#",
    "#########",
  ],
  "exit_needs": ["a", "b"],
},
# 第 3、4 关见审查报告 P0-3 的修正版地图
]
```

### 加载时**必须**做的校验（`level_data.gd`）

```gdscript
func parse(rows: Array) -> bool:
    var w := rows[0].length()
    for i in rows.size():
        if rows[i].length() != w:
            push_error("第 %d 行宽度 %d，期望 %d" % [i, rows[i].length(), w])
            return false                # ← 直接拦住 P0-3 那类排版错误
    # 再检查：恰好 1 个 P、1 个 S、1 个 E
    return true
```

> 这几行断言能省掉你至少半天调试。第 3、4 关现在的图放进去会**立刻报错**，而不是变成一个歪掉的迷宫。

## 4. 玩家控制系统（输入 → 意图）

### 4.1 输入映射（Project Settings → Input Map）

| Action        | 键                     |
| ------------- | --------------------- |
| `move_up`     | ↑ / W                 |
| `move_down`   | ↓ / S                 |
| `move_left`   | ← / A                 |
| `move_right`  | → / D                 |
| `reset_level` | R                     |
| `ui_confirm`  | Enter / Space（用内置的即可） |

### 4.2 回合锁 + 单格缓冲（`input_router.gd`）

H5 上按住方向键会以操作系统重复率疯狂触发，必须靠"回合锁"而不是 `_process` 计时：

```gdscript
extends Node
signal turned(dir: Vector2i)

var locked := false
var buffered := Vector2i.ZERO
const DIRS := {
    "move_up": Vector2i.UP, "move_down": Vector2i.DOWN,
    "move_left": Vector2i.LEFT, "move_right": Vector2i.RIGHT,
}
const MAX_BUFFER := 1        # 只缓存 1 步，防止按住时无限排队

func _unhandled_input(_e: InputEvent) -> void:
    if Game.paused: return
    for a in DIRS:
        if Input.is_action_just_pressed(a):
            _feed(DIRS[a])
            get_viewport().set_input_as_handled()
            return

func _feed(dir: Vector2i) -> void:
    if locked:
        buffered = dir          # 只覆盖，不累加
    else:
        _fire(dir)

func _fire(dir: Vector2i) -> void:
    locked = true
    turned.emit(dir)

func unlock() -> void:
    locked = false
    if buffered != Vector2i.ZERO:
        var d := buffered
        buffered = Vector2i.ZERO
        _fire(d)
```

要点：

- **用 `is_action_just_pressed`，不要用 `_process` + 计时器。** 前者由引擎保证一次按键只触发一次，浏览器重复率问题直接消失。
- **缓冲只有 1 格。** 连按两下最多排 1 步，手感跟得上又不至于"松手后自己还在走"。
- **`unlock()` 由动画播放完毕回调触发**，所以移动速度 = 动画时长，改一处即可调手感。
- 重置时必须 `buffered = Vector2i.ZERO; locked = false`（审查 P1-8）。

### 4.3 触屏

不用虚拟摇杆（那是给 8 方向自由移动的），用 **4 个 48×48 的 `Button`** 摆在屏幕下方两角，按下时调 `_feed()` 同一个函数。移动端显示条件：

```gdscript
if OS.has_feature("mobile") or DisplayServer.is_touchscreen_available():
    touch_pad.visible = true
```

> Godot 4.7 内置 `VirtualJoystick` 节点，但**不要用**：摇杆会产生连续方向值，而本游戏只需要 4 个离散方向，还得自己加死区和取整，纯属自找麻烦。

## 5. 影子延迟行动系统

这是全游戏唯一的"特色系统"，但它**只有一行状态**：

```gdscript
var pending: Vector2i = Vector2i.ZERO   # 上一拍输入；ZERO = 无历史
```

结算代码（顺序结算方案 A）：

```gdscript
# 1) 影子：按旧方向移动
var ns := shadow
if pending != Vector2i.ZERO:
    var t := shadow + pending
    if not is_blocked(t) and t != player:      # 不能进墙/门/对方所在格
        ns = t
        ev.shadow_moved = true

# 2) 本体：按新方向移动
var np := player
if input_dir != Vector2i.ZERO:
    var t := player + input_dir
    if cell(t) == DOOR and not doors_open.has(t):
        if has_key:
            doors_open[t] = true               # 本拍只开门，不移动
            has_key = false
            ev.door = true
    elif not is_blocked(t) and t != ns:        # 用影子"结算后"的位置判定
        np = t
        ev.player_moved = true

player = np
shadow = ns
pending = input_dir                            # 被挡也记录（规则 §3-6）
```

注意第 2 步的 `t != ns`：这里是 `ns`（影子**新**位置）而不是 `shadow`（旧位置），这就是"顺序结算"的物理含义——影子先走了，它空出来的格子本体可以进。写错成 `shadow` 就会出现"本体永远贴着影子走不动"的怪现象。

### 让玩家"看见"延迟（可读性设计，不可省）

| 手段        | 实现                            | 成本    |
| --------- | ----------------------------- | ----- |
| HUD 方向箭头  | 一个 Sprite2D，按 `pending` 旋转/换帧 | 10 分钟 |
| 影子身前淡灰箭头  | 同上，画在影子脚下                     | 15 分钟 |
| 移动残影      | 每拍在旧位置生成一个 0.3s 淡出的 Sprite2D  | 20 分钟 |
| 影子先动、本体后动 | tween 间隔 60ms                 | 5 分钟  |

这四项加起来不到 1 小时，但直接对应评审的"玩法 30%"。**先做这四项，再做美术。**

## 6. 机关系统：统一"锁存"模型

审查报告 P0-1 的结论落到代码上非常省事——**所有开启都是单向的**，用一个只增不减的集合表达：

```gdscript
var doors_open := {}          # Vector2i -> true
var latched := {}             # "a"/"b" -> true，已触发过的压力板
var exit_open := false
var has_key := false
```

每拍结算末尾：

```gdscript
# 压板（本体或影子所在格）
if plates.has(player): latched[plates[player]] = true
if plates.has(shadow): latched[plates[shadow]] = true

# 出口：条件一次性满足即永久开启
if not exit_open and not exit_needs.is_empty():
    var all := true
    for id in exit_needs:
        if not latched.has(id): all = false
    if all:
        exit_open = true
        ev.exit = true

# 胜利
if exit_open and cell(player) == EXIT:
    ev.win = true
```

优点：不需要处理"门关上把角色夹在里面"这种边界情况——**因为它根本不会发生**。这是把规则设计得简单带来的实现红利。

### 关卡元素与视觉约定的对应

| 元素  | ASCII       | 行为      | 视觉（形状 + 颜色双编码）          |
| --- | ----------- | ------- | ----------------------- |
| 墙   | `#`         | 阻挡      | 深色砖块，有明显边缘              |
| 地面  | `.`         | 可走      | 浅灰石纹                    |
| 本体  | `P`         | —       | 琥珀色，**圆形**轮廓 + 披风       |
| 影子  | `S`         | 重放      | 蓝紫色，**方形**轮廓 + 半透明      |
| 压力板 | `a` `b` `p` | 站上即触发   | 青色圆环，触发后**实心发光**        |
| 锁门  | `D`         | 关闭时阻挡   | 金色竖栅栏，开启后仅剩门框           |
| 钥匙  | `K`         | 本体拾取    | 金色钥匙，拾取后消失              |
| 出口  | `E`         | 开启后本体进入 | 拱门，未开启时**两盏小灯熄灭**，开启后点亮 |

> 出口那两个小灯是对审查 P2-2 的回应：玩家不用读文字就知道"我还差两块板"。

## 7. 场景划分

**只做 2 个 `.tscn`（+1 个可选）**，全部挂在同一个常驻场景里。

```
Main (Node2D)                        main.gd
├── World (Node2D)                   world_view.gd
│   ├── Terrain (TileMapLayer)       静态地图（地面/墙/门/板）
│   ├── Items (Node2D)               钥匙、出口小灯（动态显隐）
│   ├── Echo (Sprite2D)              移动残影池
│   ├── Shadow (Actor 实例)
│   └── Player (Actor 实例)
├── UI (CanvasLayer)                 hud.gd
│   ├── HUD                          关卡名 / 钥匙图标 / 待执行箭头 / R 按钮
│   ├── TitleScreen                  标题 + 开始
│   ├── RuleCard                     规则页（2 步图示）
│   ├── WinOverlay                   通关
│   ├── EndingScreen                 结尾
│   └── TouchPad                     触屏方向键
└── (Audio 用普通的 AudioStreamPlayer 子节点)
```

**为什么不用 `change_scene_to_file`**：切场景会把 Autoload 之外的一切重建，容易出现"切到第 2 关，第 1 关的标量状态还在"的诡异 bug；而且 H5 上切场景有一次明显的黑屏。用叠层 + `visible` 切换，代码量更少，过渡还能加淡入。

`actor.tscn` 本体和影子共用一个场景，只换 `texture` 和 `modulate`，避免两份代码走偏。

## 8. 关卡管理与流程（`game.gd` Autoload）

```gdscript
extends Node
signal level_loaded(index: int)
signal won()

var index := 0
var resolver: TurnResolver
var paused := false

func start_level(i: int) -> void:
    index = i
    var def: Dictionary = Levels.LEVELS[i]
    resolver = TurnResolver.from_ascii(def["map"], def["exit_needs"])
    level_loaded.emit(i)

func next_level() -> void:
    if index + 1 >= Levels.LEVELS.size():
        # 进结尾
        return
    start_level(index + 1)

func restart() -> void:
    start_level(index)      # 重建 resolver = 完整重置，天然干净
```


**重置用"重建对象"而不是"逐字段回滚"**：少写 15 行、少 5 个潜在漏项 bug。这是本方案里最划算的一个取舍。

## 9. H5 导出方案

### 9.1 项目设置（一次性，务必逐项核对）

| 设置项 | 值 |
|---|---|
| `rendering/renderer/rendering_method` | `gl_compatibility` |
| `rendering/renderer/rendering_method.mobile` | `gl_compatibility` |
| `display/window/size/viewport_width` | `320` |
| `display/window/size/viewport_height` | `180` |
| `display/window/size/window_width_override` | `960`（编辑器里看着舒服） |
| `display/window/stretch/mode` | `canvas_items` |
| `display/window/stretch/aspect` | `keep` |
| `display/window/stretch/scale_mode` | `integer` |
| `rendering/textures/canvas_textures/default_texture_filter` | `Nearest`（0） |
| `application/run/max_fps` | `60` |

### 9.2 导出预设

`Project → Export → Add → Web`，关键开关：

| 选项 | 值 | 原因 |
|---|---|---|
| **Thread Support** | **关**（4.3 起默认关） | 开了就需要服务器发 COOP/COEP 头，否则**白屏**。关掉后任何静态托管都能跑 |
| Extensions Support | 关 | 同上，会要求 SharedArrayBuffer |
| Progressive Web App | 关 | 不需要离线安装 |
| Export Path | `build/web/index.html` | 产物是 index.html + .wasm + .pck + .js + .png |

命令行导出（做 CI 或批量出包时用）：

```bash
godot --headless --export-release "Web" build/web/index.html
```

### 9.3 本地验证（这一步不做，后面一定踩坑）

```bash
cd build/web && python3 -m http.server 8000
# 浏览器打开 http://localhost:8000
```

> **双击 `index.html` 一定打不开**（`file://` 协议下 wasm 加载被浏览器阻止）。必须走 http。单线程导出不需要任何响应头，`python3 -m http.server` 就够。

### 9.4 体积与托管

- `.pck`：几百 KB（纯像素图 + 几段 wav）。
- `.wasm`：引擎本体，**未压缩约 30–40 MB**，gzip 后约 10 MB。这是 H5 的固定成本，跟你的游戏内容无关。
- 因此**托管方必须开 gzip/brotli**：Netlify / Vercel / Cloudflare Pages 自动开；GitHub Pages 对 wasm 不做压缩，首屏会很慢。
- ⚠️ Cloudflare Pages 有**单文件 25 MiB 上限**，未压缩的 wasm 可能超；如果要用它，先确认压缩后的传输体积，或换 Netlify。
- 比赛提交若要求"一个网址"，建议 Netlify 拖拽部署（`build/web` 整个文件夹拖进去），30 秒出链接；若要求"压缩包"，直接 zip 该文件夹，注意 **index.html 必须在根目录**。

### 9.5 H5 专项坑位清单（逐条测）

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | 音频自动播放限制 | 进游戏没声音，按键后才有 | 标题页要求按任意键才开始，音频在此时解锁 |
| 2 | 键盘焦点 | 嵌在 iframe 里按键无反应 | 开始前先 `click` 一次画布；标题页的"开始"按钮天然解决 |
| 3 | 方向键滚动页面 | 按 ↓ 整页往下滚 | Godot 默认模板已 `preventDefault`；嵌入自己页面时需检查 |
| 4 | 按住方向键连发 | 一步变五步 | 回合锁 + `is_action_just_pressed`（§4.2） |
| 5 | 高分屏模糊 | 像素被插值成糊块 | `Nearest` + `integer` 缩放 |
| 6 | 浏览器缩放 / 窗口比例 | 地图被拉扁 | `aspect = keep`（留黑边，不变形） |
| 7 | Safari 触屏 300ms 延迟 | 点方向键反应慢 | 按钮设 `button_mask` 直接响应 `pressed`，用 `ButtonDown` 而非 `ButtonUp` 触发 |
| 8 | 手机竖屏 | 320×180 横版被缩得很小 | 加"请横屏"提示层；或强制 `display/window/handheld/orientation = landscape` |
| 9 | 刷新后从头开始 | 正常 | 本作无存档需求，不做 localStorage |
| 10 | 现场演示断网 | 打不开 | 演示视频 + 本地导出包双备份 |

## 11. 风险与降级方案

| 风险 | 概率 | 降级方案 |
|---|---|---|
| TileSet 配置卡住 | 中 | 放弃 `TileMapLayer`，用 72 个 `Sprite2D` 直接摆（12×6 最多 72 个节点，性能毫无压力），逻辑完全不变 |
| 像素美术来不及 | 高 | 先用**纯色块 + 形状区分**（圆=本体、方=影子、环=压板）跑通全流程，最后 2 天统一替换贴图。形状编码本身也是无障碍设计 |
| 音效资源找不到 | 中 | 用 `AudioStreamGenerator` 或干脆**只做 3 个音**（移动、开门、通关），其余留空 |
| H5 导出白屏 | 中 | 先确认 Thread Support 关闭；再换 `gl_compatibility`；最后用官方 `serve.py` 验证是否服务器问题 |
| 第 4 关调不出"有难度但不无解" | 中 | 退回已验证的 12 拍布局（审查报告 P0-3 修正版），时间不够就用它 |
| 工期失控 | 中 | 冻结范围：**4 关必须全通、H5 必须能跑、视频必须有**，其余（剧情、设置、装饰）全砍 |
