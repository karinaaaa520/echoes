## 1. 先更正上一版的错误结论

上一版报告写「第 17 拍本体从没走到 b，所以这块板只能靠影子踩」，并把它当成「影子必需」的证据。**这个推断是错的**：解法没走到 b，不等于走不到 b。

复现你的反馈（`docs/tools/level_check.py` 的反事实模型，见第 4 节）：

```
=== 旧第三关 双影回廊 ===
  板 a @(3,2)  本体可达=True
  板 b @(9,5)  本体可达=True        ← 本体自己就能踩
  本体单独路线: ❌ 可通关 D D R U R D R R R R D D R R R U U L L（19 拍）
  真实双体规则: ✅ 可通关 D R R R R R U U R R D L D R R R R（17 拍）
```

旧关卡里两块板都在本体可达区域内，**影子只是"顺路"踩了一块**。玩家按住方向键乱走也能过，所以你的试玩结论成立。

## 2. 新第三关：影牢

### 2.1 设计目标：让"影子在哪、什么时候动"变成必须计算的东西

前两关教的是"影子会跟着走"，但它们都可以**完全不看影子**通过。第三关把影子的**位置**变成硬约束：

> 你的影子被关在右下角的壁龛里。板 b 就在它正下方一格 —— 但中间隔着一堵墙。  
> 影子只会重复你的方向，所以你必须**先按那个方向走**，它才会跟着走。  
> 而它慢一拍：你现在按的键，是它下一拍才执行的动作。

玩家要做的推理：**看壁龛的形状（钩形）→ 倒推出影子需要的四个方向（右、下、下、左）→ 把这四个方向混进自己的路线里**。这是"预测影子轨迹"而不是"跟着影子跑"。

三段递进：

|             | 第 1 关 | 第 2 关 | 第 3 关「影牢」       |
| ----------- | ----- | ----- | --------------- |
| 最短解         | 4 拍   | 6 拍   | **17 拍**        |
| 影子是否必需      | 否     | 否     | **是（结构上）**      |
| 玩家要不要算影子的位置 | 不要    | 不要    | **要，而且是四步序列**   |
| 新教的东西       | 影子慢一拍 | 影子能压板 | **影子只能走你走过的方向** |

### 2.2 地图（11×8）

```text
###########
#P...#...E#
#.a..D....#
#....######
#.K..##S.##
#....###.##
#....##b.##
###########
```

| 元素   | 坐标    | 说明                |
| ---- | ----- | ----------------- |
| 本体 P | (1,1) | 左屋左上角             |
| 影子 S | (7,4) | **在壁龛内**，四周全是墙    |
| 板 a  | (2,2) | 本体第二步就能踩到         |
| 钥匙 K | (2,4) | 左屋                |
| 锁门 D | (5,2) | 左屋通往右厅的唯一通道       |
| 出口 E | (9,1) | 右厅右上角，需要 a + b    |
| 板 b  | (7,6) | **壁龛最深处，本体永远到不了** |

壁龛内部是 5 格钩形通道，`S` 与 `b` 之间那格 (7,5) 是墙：

```text
S .          (7,4) 影子起点 → (8,4)
# .          (7,5) 墙   → (8,5) 钩底
b .          (7,6) 板 b  ← (8,6)
```

影子只能 **右 → 下 → 下 → 左** 四步绕过去。

## 3. 「影子必需」的验收证据

### 3.1 证据一：板 b 本体结构上不可达（不是"没走到"，是"走不到"）

`test_level3.gd` 第 [3] 组：从本体起点泛洪（门按最宽松的"全开"算），

```
[PASS] 本体可达区域不含 b 所在格
[PASS] 逐一确认 (7,6) 不在本体可达集合里
[PASS] 影子起点 (7,4) 也不在本体可达区域里
[PASS] 本体活动区域正常（33 格）
[PASS] b 在影子的壁龛连通域内
[PASS] 壁龛恰好 5 格（S + 钩形通道 + b）
```

本体可达 33 格，壁龛 5 格，两个连通域**完全不相交**。出口需要 a+b，而 b 只存在于壁龛里 —— 所以任何"只用本体"的路线都不可能满足出口条件。这是结构性证明，不依赖搜索深度。

### 3.2 证据二：反事实全状态搜索

三个独立模型（口径在报告里写死，不是"忽略影子"这种含糊说法）：

| 模型              | 定义                         | 结果                        |
| --------------- | -------------------------- | ------------------------- |
| **A. 影子不存在**    | 影子不占格、不挡路、不触发任何机关          | ✅ 不可通关                    |
| **B. 影子不触发压力板** | 影子在场上、照常挡路，但只有本体能压板        | ✅ 不可通关                    |
| **C. 引擎侧复算**    | GDScript 里重写 A，用真实关卡数据 BFS | ✅ 不可通关（`test_level3` [4]） |

模型 A/B 由 `docs/tools/level_check.py` 输出：

```
【3 影牢】影子必要性审计
  本体可达 33 格；本体**结构上踩不到**的板: ['b']
  反事实 1（影子不存在）      : ✅ 不可通关
  反事实 2（影子不触发压力板）: ✅ 不可通关
  可达状态 3828 个，其中死局 0 个（每个状态都还能赢）
```

再加一组**对照组**，防止"地图被写死成走不通"：

```
[PASS] 对照组（只要 a）本体单独可以通关      ← 同一张图，去掉 b 的要求就能过
[PASS] 只要 b 时本体单独仍然不能通关        ← 卡点确实来自 b
```

### 3.3 证据三：关键回合的因果关系（删掉它就不成立）

第 5 拍的 `L` 是这次解法的枢纽。把**这一个输入**换成 `D`，其余 16 拍完全一样：

```
[PASS] b 没有亮（影子撞下墙被弹回）
[PASS] 出口没有开启
[PASS] 17 拍走完也没有通关
[PASS] 影子被 (8,7) 下墙弹回，最终停在 (8,4)
```

第 5 拍之前影子停在钩底 (8,6)、与 b 只差一格；第 5 拍的 `L` 让它在第 6 拍迈出那一步。**影子延迟一拍的机制在这里发生因果作用**：玩家第 5 拍给的方向，影子第 6 拍才执行。

### 3.4 证据四：不会硬锁

- 模型侧：3828 个可达状态**全部**能赢（死局 0）。
- 引擎侧：把第 5 拍打错之后，继续给 `D D L R U R R R`，第 4 个补救输入就让影子重新踩到 b，最终仍然通关。
- 实机：第三关中途按 R →

```
[reset] 回到初始状态 { "turn": 0, "player": (1, 1), "shadow": (7, 4), "pending": (0, 0),
                      "key": false, "keys_left": 1, "doors": 0, "plates": 0,
                      "exit": false, "won": false }
```

影子被关在密封壁龛里，**永远不会挡本体的路**，所以本体那边不存在"被影子堵住"的死局来源。

### 3.5 证据五：难度来自推理，不来自长度

- 壁龛的形状（`S` 与 `b` 之间那堵墙）是**可见的**，钩形通道一眼能看出"要绕过去"。
- 需要的四个方向可以从形状直接读出来，不依赖任何隐藏规则。
- 不靠"多走 10 步"制造难度：17 拍里有 5 拍是必要的影子驱动，其余是钥匙/门/路程。
- 随机乱走命中率 **0.1%**（3000 次 40 拍随机走位，仅 3 次碰巧通关）—— 说明它不是"瞎按也能过"。

## 4. 可解性检查方法（模型与引擎是否一致）

| 层    | 工具                                            | 结论                        |
| ---- | --------------------------------------------- | ------------------------- |
| 设计层  | `docs/tools/level_check.py`，BFS 全空间，顺序结算      | 17 拍可解（同时结算假设下也是 17 拍，稳健） |
| 语义审计 | 同文件新增的必要性审计（3 个反事实模型 + 死局统计）                  | 见 §3                      |
| 引擎层  | `tests/test_level3.gd`，用真实 `TurnResolver` 逐拍跑 | 17 拍位置**逐拍一致**，60 条断言全过   |

一致性口径：`level_check.py` 与 `turn_resolver.gd` 的规则对应关系是"影子先动→本体后动→只本体拾钥匙→逐块永久锁存→每拍末判胜"。这次专门加了一条对照：`test_level3` 里 17 拍的 **每个** 本体/影子坐标都写成常量数组，与 Python 模型输出比对，任何一拍漂移都会 FAIL。

另外修掉了验证器的一个崩溃：`main()` 的逐拍追踪仍在用旧规则键名 `V2 顺序 + 出口锁存`，规则表改名后跑不到追踪就 `KeyError`。现在键名与规则表一致，`trace()` 正常输出。

## 10. 回答你的四个问题

**1. 如果忽略影子，第三关还能通关吗？**  
不能。板 b 在密封壁龛里，本体可达 33 格与壁龛 5 格完全不相交，而出口需要 a+b。三种口径的反事实搜索（影子不存在 / 影子不压板 / 引擎侧重算）都是"无解"，另有对照组证明"只要 a"时同图可通。

**2. 哪个关键回合证明影子是必要的？**  
第 6 拍：影子从 (8,6) 迈到 (7,6)，踩亮 b，出口当场开启。删掉第 5 拍的 `L`（改成 `D`），影子就永远到不了那一格，17 拍走完也不通关。

**3. 影子延迟行动具体如何参与解谜？**  
影子执行的是**你上一拍的方向**。玩家第 2~~5 拍按 `R D D L`，影子在第 3~~6 拍才依次执行 `R D D L`，画出钩形轨迹。也就是说：玩家必须"先走过影子的路"，而且要用自己的位移去喂它 —— 影子不是跟随者，是被你驱动的第二个身体。

**4. 通关输入序列？**  
`D R D D L U U R R R R R R U R R R`（17 拍，逐拍状态见 §2.3）。

**是否实际运行通关与重开**：是。桌面窗口模式与 H5 浏览器各跑了一遍完整三关；第三关中途按 R 的复位状态逐项打印核对（§7.1）。

**仍未验证**：真人试玩能否自行发现解法、非 Chrome 浏览器、触屏、桌面 Release 包（§8）。
